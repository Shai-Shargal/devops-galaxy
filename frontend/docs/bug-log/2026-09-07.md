## 🐛 Bug #1: Add Service Feature Completely Broken

**Status:** ✅ Fixed  
**Date Found:** 2026-09-06 (continued 2026-09-07)  
**Date Fixed:** 2026-09-07  
**Severity:** CRITICAL - Core feature non-functional  

### Description
When users clicked "+ Add Service" and filled in the form, the service appeared to be added to the system (stats updated from 6→7), but **no visual dot appeared in the galaxy**. Services that were successfully added to the backend state were invisible.

### Root Cause
**The real problem:** App.jsx and Services.jsx were each calling `useServices()` separately, creating **TWO independent state instances**:
- App's state: Had 7 services ✅
- Services' state: Had 6 services (never updated) ❌

When a new service was added through App's `addService`, it updated App's state but NOT Services' state, so the Services component never re-rendered with the new service.

Additionally, App was importing from the **wrong Services file**:
- App imported: `./components/Services` (old file, 19KB, 400+ lines)
- But refactored component was at: `./components/Services/Services.jsx` (new file)

So all fixes made to the refactored component were ignored!

### Impact
- ❌ Users could not add new services
- ❌ Add Service button appeared to work but did nothing visually
- ❌ Core feature blocked
- ❌ Terrible user experience

### Reproduction Steps
1. Click "+ Add Service" button
2. Fill in service name, team, status
3. Click "Create Service"
4. **Expected:** New dot appears in galaxy
5. **Actual:** Nothing happens visually

### Fix Applied

**Step 1: Import Correct Component**
```javascript
// Before: importing old file
import Services from './components/Services'

// After: importing refactored component
import Services from './components/Services/Services'
```
Also deleted the old Services.jsx file to prevent confusion.

**Step 2: Share State Between App and Services**
- Moved `useServices()` hook to App only
- App passes all state/methods to Services as props:
  ```javascript
  <Services
    services={services}
    selectedService={selectedService}
    selectService={selectService}
    clearSelection={clearSelection}
    updateService={updateService}
    getDependencies={getDependencies}
    getDependents={getDependents}
  />
  ```
- Services no longer calls `useServices()` internally
- Services uses only the props passed from App
- **Result:** Single shared state instance!

**Step 3: Fix CSS Import Path**
Services component was in a subfolder but importing CSS from old location:
```javascript
// Before (wrong)
import './Services.css'

// After (correct)
import '../Services.css'  // Go up one level
```

## 🐛 Bug #2: Services Getting Stuck After 7 Services Added

**Status:** ✅ Fixed  
**Date Found:** 2026-09-07 (during user testing)  
**Date Fixed:** 2026-09-07  
**Severity:** HIGH - Scalability issue  

### Description
When users added more than 7 services, new services would:
- ❌ Stop rotating
- ❌ Get stuck in place
- ❌ Not animate properly
- ❌ System appeared to break

### Root Cause
The spiral positioning math had too small a maximum:
```javascript
maxTheta: 8 * Math.PI  // Only allowed ~8π = 25.13 radians
```

With services placed every 0.6 radians:
- Service 1: 0.5 rad
- Service 2: 1.1 rad
- Service 3: 1.7 rad
- ...
- Service 7: 4.1 rad
- Service 8: 4.7 rad (wraps around due to modulo)

When wrapping occurred, services overlapped or got positioned off-screen, breaking the animation.

### Impact
- ❌ Maximum 7 services could be added
- ❌ 8+ services would fail/get stuck
- ❌ Limits scalability of the system
- ❌ Confusing user experience

### Reproduction Steps
1. Add 7 services (works fine)
2. Add 8th service
3. **Expected:** 8th service rotates with others
4. **Actual:** Gets stuck, stops moving

### Fix Applied
Expanded the spiral size to accommodate more services:

```javascript
// Before
export const SPIRAL_CONFIG = {
  baseRadius: 70,
  maxRadialDistance: 100,
  maxTheta: 8 * Math.PI       // ~25.13 radians
}

// After
export const SPIRAL_CONFIG = {
  baseRadius: 70,
  maxRadialDistance: 150,      // Bigger growth
  maxTheta: 20 * Math.PI       // ~62.8 radians (2.5x larger!)
}
```

Now supports 30+ services instead of just 7!

### Testing
✅ Add 8 services - all rotate smoothly  
✅ Add 10 services - all visible  
✅ Add 15 services - spiral expands outward  
✅ All services remain animated

## 🐛 Bug #4: Duplicate Service Key Warnings

**Status:** ✅ Fixed  
**Date Found:** 2026-09-07 (during user testing)  
**Date Fixed:** 2026-09-07  
**Severity:** MEDIUM - Developer experience / Console warnings  

### Description
React warning in console:
```
Encountered two children with the same key, `service-test`. 
Keys should be unique so that components maintain their identity.
```

This happened when users added multiple services with the same name (e.g., "test").

### Root Cause
Service ID generation used only the name:
```javascript
// Before - name-based only
const serviceId = `service-${newService.name?.toLowerCase().replace(/\s+/g, '-')}`
// Result: "service-test" for any service named "test"
```

When two services had the same name, they got the same ID, violating React's key uniqueness requirement.

### Impact
- ⚠️ Console warnings (not critical, but unprofessional)
- ⚠️ Potential rendering issues with duplicate keys
- ⚠️ User confusion if services behaved unexpectedly

### Fix Applied
Added timestamp to ensure uniqueness:

```javascript
// After - name + timestamp
const serviceId = `${newService.name?.toLowerCase().replace(/\s+/g, '-') || 'service'}-${Date.now()}`
// Result: "test-1726234567890" (always unique!)
```

✅ Add 3 services all named "test"  
✅ No console warnings  
✅ Each gets unique ID (test-1726234567890, test-1726234567891, etc.)  
✅ All render correctly

**Date Found:** 2026-09-07  
**Date Fixed:** 2026-09-07  
**Severity:** CRITICAL - Architectural issue  

### Description
App.jsx was importing Services from the wrong file:

During refactoring, the Services component was moved from:
- `components/Services.jsx` (old, 19KB, 400+ lines)

To:
- `components/Services/Services.jsx` (new, refactored, 4.9KB)

But App.jsx import wasn't updated, so it kept using the old file!

### Impact

- ❌ Fix attempts didn't work because wrong file was being used
- ❌ Wasted debugging time
- ❌ Core functionality broken

### Fix Applied
1. Updated import path:
```javascript
// Before
import Services from './components/Services'

// After
import Services from './components/Services/Services'
```

2. Deleted old Services.jsx file to prevent future confusion:
```bash
rm frontend/src/components/Services.jsx
```

## 🎯 Key Learnings

1. **Duplicate Hook Instances** - Each component calling the same hook creates independent state. Must share state intentionally.

2. **Import Paths Matter** - When refactoring files, ALL imports must be updated. Easy to miss!

3. **Testing During Development** - These bugs were caught immediately by testing the "Add Service" feature.

4. **Git Cleanup** - Deleted old files to prevent confusion and accidental use.

5. **Unique IDs** - Any time users can create items with same names, IDs must include a unique component (timestamp, UUID, etc.)
